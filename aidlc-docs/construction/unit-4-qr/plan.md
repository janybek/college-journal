# Юнит 4 «Пара и отметка по QR»: план сборки

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** преподаватель на своей паре нажимает «Начать пару»; на проекторе — светлый экран с крупным QR, кодом из 4 цифр, таймером и именами отметившихся; студент на телефоне жмёт «Я на паре» и вводит код или сканирует QR; через 5 минут неотметившиеся сами получают «не был»; дальше этапы «Материал» (тема и таймер) и «Итог» (список, опоздания, халат, активность) и «Завершить пару» — или пара закрывается сама через 90 минут. Всё ложится в тот же журнал юнита 3: те же строки «Посещаемости», те же баллы, те же правила правки после пары. Ручная отметка юнита 3 остаётся как была.

**Architecture:** правила (время пары, коды, пропуск, конец окна и закрытие пары) — чистые функции в `core/lesson.js`; свой QR-кодировщик — чистый модуль `site/js/qr.js`. На сервере нет будильников: перед каждым запросом, который показывает или меняет пары, отметки и оценки, `backend/lessonSettle.js` «досчитывает» идущие пары — закрывает окно отметки и саму пару, если их срок по времени старта уже прошёл, и записывает это временем срока, а не временем запроса. Секрет кодов не хранится: он выводится из секрета сервера, id пары и времени её фактического старта. Новые действия: `lesson.*` (преподаватель пары), `checkin.*` (студент; `checkin.pass` — публичное, меняет QR на пропуск до конца окна). Новая таблица «Отметки с телефона» (номер устройства, неверные коды) и шесть колонок у «Пар». Сайт получает: «Пары сегодня» у преподавателя, экран пары с тремя этапами, кнопку в карточке «Сегодня» журнала, карточку «Я на паре» и экран ввода кода у студента.

**Tech Stack:** как в юните 3 — Node 24, ES-модули, `node --test`, встроенный `node:sqlite` (рабочий сервер), esbuild только для запасной сборки под Apps Script, сайт без сборки, `<canvas>` для QR. Новых зависимостей нет.

**Spec:** `aidlc-docs/inception/design-v1.md` (раздел 3 «Ограничения» — время и таймеры; раздел 6 «Пара и отметка»; раздел 7 — наброски экранов; раздел 8 — колонка «устройство»), таблица решений `aidlc-docs/aidlc-state.md` — строки 22.11.2026 «Порядок юнитов меняется» и «Новые правила (приняты все 12)», 23.11.2026 «Юнит 4 — вопросы до плана», «Юнит 3 принят», «Виды журнала»; план юнита 3 `aidlc-docs/construction/unit-3-zhurnal/plan.md` (модель данных, права, правила срока правки — действуют без изменений). `design-v1.md` писался под Google: сервер теперь Node + SQLite на компьютере владельца за Tailscale Funnel. Где `design-v1.md` расходится с таблицей решений или с этим планом, действуют они (пример: неначатая пара **не** становится «не проведена» сама — правило юнита 3).

**Исходное состояние:** `HEAD 442957a`, **718 тестов**, `npm run build:gas` собирается. Юниты 1–3 приняты и выложены. «Виды журнала» (решение владельца 23.11.2026: переключатель «День · Неделя · Юнит · Весь журнал» и карточка «Сегодня · пара N» с «Отметить» в `site/js/views/journal.js`, новые помощники в `site/js/journal.js`) уже в `main` (`880afac`), приняты и выложены; этот план опирается на них и ссылается на функции по имени, а не на номера строк. ## Global Constraints

Действующие правила юнитов 2–3 (переносятся без изменений):

- `core/` и `backend/` без зависимостей из npm. Dev-зависимости проекта: `esbuild`, `xlsx`, `@fontsource-variable/inter`. Новые не добавляются.
- Сайт: без сборки, без фреймворков, ничего не загружает с чужих адресов (ни CDN, ни внешних шрифтов).
- Все обработчики сервера синхронные. `handleRequest` никогда не бросает исключение и всегда возвращает объект ответа. Ошибки — `AppError(code, { fields })` из `core/errors.js`.
- Запрос сайта: `POST`, `Content-Type: text/plain;charset=utf-8`, тело — JSON `{action, token, data}`. Своих заголовков нет.
- `passwordHash` никогда не попадает в ответ сервера. Ответы собираются по полям; строки сотрудников и студентов в ответ целиком не копируются.
- Время берётся только из `platform.now()`. `Date.now()` и `new Date()` без аргумента в `core/` и `backend/` запрещены. «Сегодня» — `localDate(platform.now())` по Бишкеку (UTC+6 круглый год). Сайт часам устройства не доверяет: «сегодня» и «сейчас» он берёт из ответа сервера.
- Дата — строка `'YYYY-MM-DD'`, время — `'HH:MM'`, дата со временем — `'YYYY-MM-DD HH:MM:SS'` (`localDateTime`). Объектов `Date` в строках хранилища нет.
- В базе хранятся английские коды (`present`, `running`), на экране они переводятся словарём.
- Обработчик читает каждую таблицу не больше одного раза за запрос (`store.list`) и пишет пачкой (`insertMany`, `updateMany`, `removeMany`). `store.get`, `store.update`, `store.remove` в цикле запрещены.
- Что попадает в сборку Apps Script, остаётся чистым: `backend/api.js`, `backend/handlers/*`, `backend/*.js` (кроме `backend/node/` и `backend/store/sqliteStore.js`), `core/*` не импортируют ничего из `backend/node/`; в них нет `node:`, `require(` и слова `process` даже в комментариях (их ищет `tests/gasBundle.test.js`).
- Роли: `admin`, `dean`, `prorector`, `teacher`, `student`. У сотрудника роли хранятся строкой через запятую; у одного человека может быть несколько ролей (`dean,teacher`).
- Любая фраза на экране идёт через ключ словаря. Наборы ключей в `ky`, `ru`, `en` одинаковые (`tests/i18n.test.js`). Названия дней и месяцев — из словаря, без `Intl`.
- Данные с сервера, от пользователя и из файлов попадают на страницу только как текст (`textContent`, помощники из `site/js/ui.js`), никогда через `innerHTML`.
- Цвета — hex или rgb, без `oklch()`. Новые экраны берут цвета и размеры из переменных `site/css/app.css`. Код и картинки платного шаблона не копируются.
- Две темы, тёмная по умолчанию; каждый экран проверяется в обеих. **Исключение — экран пары: он всегда светлый** (решение владельца от 20.11.2026).
- Студенческие экраны — для телефона шириной 360 px: без бокового меню, текст не мельче 16 px, кнопки и ссылки-кнопки не ниже 44 px.
- Настоящих данных студентов и сотрудников в репозитории нет: ни в коде, ни в тестах, ни в отчётах, ни на скриншотах. `dev/data/` и `build/` — в `.gitignore`.
- Локальный стенд — только порт 5273. Рабочий сервер (порт 5373), папки `D:\Журнал колледжа — сервер`, `D:\Журнал колледжа — данные`, `C:\JournalBackups`, файлы `serve.local.json` и `dev/data/real.json` агенты не открывают, не запускают и не правят.
- У пары вся группа целиком (подгрупп нет). 1 пара = 2 часа.
- Сообщения коммитов на английском; в конце строка `Co-Authored-By` с той моделью, которая на самом деле писала коммит. Агент коммитит **только свои файлы по имени** (не `git add -A`) и оставляет `git status` чистым.
- `git push` и обновление рабочего сервера — только по прямой просьбе владельца.
- **Данные студентов — строго.** Студент получает в ответе только своё: ни id, ни ФИО, ни отметок другого студента. Проверяется поиском по всему JSON ответа, а не только кодом ответа.
- **Права проверяются попыткой обойти защиту.** Отказ — и ничего не записано: тест сравнивает снимок таблиц до и после.
- **Журнал изменений** (правило 6 владельца) пишется в том же запросе; строки не меняются и не удаляются никогда. Таблицы «Посещаемость», «Итоги юнитов», «Журнал изменений» пишут только `backend/journalData.js`, новые `backend/lessonSettle.js`, `backend/checkinData.js` (только «Посещаемость») и `dev/seed.js` через их функции.
- **Всё или ничего.** Запрос с одной плохой строкой не записывает ничего (единственное исключение — неверный код, ниже).
- Причина правки — текст до 300 знаков, хранится и показывается как текст.
- Стенд и браузер агентов: перед экранными задачами стенд координатора на 5273 остановлен, агент поднимает свой. Браузер для проверки — только headless Chrome с временным профилем и ключами `--disable-sync --disable-extensions`; не Edge. Процессы агент останавливает **только по своему номеру (PID)** — те, что запустил сам; никогда по имени программы или заголовку окна. Браузер и учётные записи владельца агенты не трогают.
- Вход на стенде: `admin`, `dean` (деканат и преподаватель), `prorector`, `teacher1`…`teacher3`, студенты `S1001`…; пароль — константа `DEV_PASSWORD` в `dev/seed.js`. В отчётах и скриншотах пароль не пишется.

Новые правила юнита 4:

- **Коды — только преподавателю пары.** Текущий и следующий код, QR-ключ шага (`code`, `qr`) и ключ пары уходят только в ответе `lesson.get`/`lesson.start`/`lesson.endCheckin`/`lesson.finish` тому, кто ведёт эту пару (`pair.teacherId`), и только пока идёт окно отметки. Их нет в ответах студенту, деканату, проректору, другим преподавателям, в журнале, в «Журнале изменений», в расписании, в журнале работы сервера. Ключ пары не хранится нигде (`pairKey` выводится при каждом запросе).
- **Время — только сервера.** Окно, шаги кода, конец пары считаются от `pairs.startedAt` и `platform.now()`. Сайт показывает «осталось» по числу миллисекунд из ответа и `performance.now()` после ответа; часы устройства не используются ни для решения, ни для показа. Сервер не принимает от сайта никакого времени.
- **Без будильников на сервере.** Ни `setInterval`, ни `setTimeout` в `backend/` и `core/`: конец окна и закрытие пары записывает `settleLessons` в начале запросов (задача 6) временем срока (`checkinUntil`, `startedAt + 90 мин`), а не временем запроса. Повторный досчёт ничего не пишет.
- **Неверный код — единственный отказ, который пишет.** Чтобы счётчик неверных кодов не откатился вместе с транзакцией SQLite, неверный код отвечает `ok: true` с `{ result: 'wrong_code', attemptsLeft }` и пишет одну строку «Отметок с телефона» (`result: 'wrong'`). Все остальные отказы `checkin.*` — обычные `AppError` без записи.
- **`checkin.pass` — единственное новое публичное действие.** Его ответ — только `{ pass, checkinLeftMs }`: ни названия предмета, ни имён.
- **QR-картинку рисует свой кодировщик** `site/js/qr.js` (без библиотек и без чужих адресов).
- **Юнит 3 не меняется для пар, которые не начинали кнопкой.** Все прежние тесты остаются зелёными без правок, кроме прямо названных в задаче (перечисленные в задаче 3 проверки списков таблиц, колонок и прав).
- **Проверка задач** (правило 12 и правило экономии от 22.11.2026): после каждой задачи 1–9 — облегчённая проверка (sonnet, короткий отчёт); пробы на права и данные — **строгие** для задач 3, 6, 7, 8 (обход, снимок таблиц, поиск в JSON). Экранные задачи: проверка ИИ — только задачи 11 и 12 (правка отметок и данные студента, номер устройства, пропуск); задачу 10 владелец принимает блоком. Общая проверка юнита — одна, в конце, строгая, opus, с пробными скриптами против настоящего кода.
- **Модели.** «Логика», «Сервер», «Экраны», проверяющий — sonnet; сверка плана и общая проверка — opus. Модель указывается явно в каждом поручении.

## Review Focus

1. **Коды не утекают.** Студент, проректор, деканат, преподаватель другой пары и преподаватель предмета на паре замены не получают кода, QR-ключа и ключа пары ни одним действием; в ответах `checkin.*`, `journal.*`, `schedule.*`, `student.grades` нет полей `code`, `qr` и значения текущего QR-ключа. Тесты — задачи 7, 8.
2. **Чужой студент.** Студент другой группы, выключенный, переведённый в другую группу после старта, студент с неверным `pairId` (массив, число, строка с пробелами) — отказ, ничего не записано (снимок «Посещаемости», «Отметок с телефона», «Пар»). Тесты — задача 8.
3. **Не тот код и не тот пропуск.** Код другой пары; код 2–4 шагов назад («код сменился», без счёта); код 5 шагов назад и будущий — неверный; код после конца окна; пропуск другой пары, с другого устройства, просроченный, подделанный (изменён срок), токен входа вместо пропуска и пропуск вместо токена входа. Тесты — задачи 2, 8.
4. **Подбор кода.** Пять неверных кодов — шестой, даже верный, отказ `too_many_codes`; счётчик — на студента и пару (на другой паре снова пять); счётчик **сохраняется на SQLite**, хотя запрос отвечает отказом по смыслу. Тесты — задача 8.
5. **Один телефон.** Второй студент с того же устройства на той же паре — `device_used`; тот же студент со второго устройства — «уже отмечен»; ложную отметку преподаватель меняет на «не был», студент второй раз не отметится, устройство остаётся занятым. Тесты — задачи 6, 8.
6. **Время.** Старт с 07:50:00 при звонке 08:00, в 07:49:59 — рано; после 09:30 — поздно; шаг кода ровно каждые 15 с от старта; окно закрывается ровно через 5 мин; пара — ровно через 90 мин; досчёт пишет время срока, даже если запрос пришёл через час; повторный досчёт ничего не пишет; полночь по Бишкеку. Тесты — задачи 1, 4, 6.
7. **Автоматическое «не был».** Только активным студентам группы пары без отметки на конец окна; не выключенному, не переведённому, не пришедшему в группу позже; стоящие отметки (по коду и рукой) не трогаются; не отметился никто — «не был» никому; пара без единой отметки при закрытии — снова «не заполнена» (`planned`). Тесты — задачи 4, 6.
8. **Встреча с журналом юнита 3.** Идущая пара считается проведённой; пара, начатая до звонка, не «будущая» для отметки; смена статуса стоящей отметки на идущей паре — строка журнала изменений, первая ручная отметка, активность и халат во время пары — нет; после закрытия — правила юнита 3 (3 дня свободно, потом два изменения с причиной); правка деканата на идущей паре — всегда с причиной и в журнал изменений; «не проведена», сброс отметок, перенос и отмена идущей пары — `pair_locked`; прежние 718 тестов зелёные (кроме проверок, названных в задаче 3). Тесты — задача 6.
9. **Права на пару.** Начать, открыть, закончить отметку и завершить пару может только тот, кто её ведёт; деканат, проректор, студент, другой преподаватель — `forbidden`; второй «Начать» той же пары — та же пара, без нового старта; «Начать» следующей пары закрывает прежнюю идущую пару этого преподавателя. Тесты — задача 7.
10. **Нагрузка.** 25 студентов отмечаются подряд на SQLite с ~4000 строк «Посещаемости» — в пределах времени теста; один студент дважды — одна строка; досчёт не повторяет записей. Тест — задача 8; проба на стенде — задача 13.
11. **QR читается.** Кодировщик даёт верные коды Рида — Соломона, строки формата и версии; ссылка обычной длины — версия не выше 6; телефон владельца читает QR со стенда (блок 1). Тесты — задача 5.
12. **Экраны.** Экран пары светлый и после ухода возвращает тему устройства; на этапе «Отметка» нет списка с баллами; QR не меньше 60 % высоты экрана в полноэкранном режиме; код меняется без ожидания опроса; скрытая вкладка не опрашивает сервер и обновляется при возвращении; двойное нажатие «Отметиться» шлёт один запрос; студент на 360 px без горизонтальной прокрутки. Проверка на стенде — задачи 10–12.

Проверяющий задач 6–8 отдельно убеждается: каждая проверка «ничего не записано», «в ответе нет кода», «каждая таблица один раз» написана настоящим `assert` по данным.

## Модель данных

`core/schema.js` (задача 3). Новая таблица — в конец `SCHEMA`, после `changeLog`; колонки пар — в конец `pairs.columns`, после `substitute`.

```js
export const MARK_SOURCES = ['teacher', 'code', 'qr', 'auto'];   // рукой, по коду, по QR, «не был» в конце окна
export const CHECKIN_WAYS = ['code', 'qr'];
export const CHECKIN_RESULTS = ['ok', 'wrong'];

// pairs: + col('startedAt', 'фактический старт'), col('startedBy', 'кто начал'), col('checkinUntil', 'отметка до'),
//          col('checkinClosed', 'отметка закрыта', 'bool'), col('finishedAt', 'пара закрыта'), col('finishedBy', 'кто закрыл')
checkins: {
  sheet: 'Отметки с телефона', prefix: 'ci',
  columns: [col('id', 'id'), col('pairId', 'пара'), col('studentId', 'студент'), col('device', 'устройство'),
    col('way', 'как'), col('result', 'результат'), col('at', 'когда')],
},
```

Смысл:

- **Пара, идущая кнопкой:** `status: 'running'`; `startedAt` — `'YYYY-MM-DD HH:MM:SS'` нажатия «Начать пару»; `startedBy` — id преподавателя; `checkinUntil` — конец окна (старт + 5 мин или раньше по «Закончить отметку»); `checkinClosed` — конец окна досчитан («не был» записан или никому не нужен); `finishedAt`, `finishedBy` — закрытие (`finishedBy: ''` — закрылась сама через 90 минут). У пар, которые не начинали кнопкой (все прежние), эти поля пустые (`''`, `false`).
- `LESSON_CLEAR` = `{ startedAt: '', startedBy: '', checkinUntil: '', checkinClosed: false, finishedAt: '', finishedBy: '' }` — пара без отметок, вернувшаяся в «не заполнена».
- **Посещаемость:** отметка студента — та же строка, что у юнита 3: `source: 'code' | 'qr'`, `markedBy` — id студента, `markedAt` — время отметки, `status: 'present'`. «Не был» в конце окна — `source: 'auto'`, `markedBy: ''`, `markedAt` = `checkinUntil`. Правка преподавателя, как в юните 3, ставит `source: 'teacher'` и своё `markedBy`.
- **Отметки с телефона:** строка на каждую удачную отметку (`result: 'ok'`, номер устройства, `way`) и на каждый неверный код (`result: 'wrong'`). Отказы без записи (окно закрыто, чужая группа, устройство занято…) строк не дают. Таблица недоступна через `dir.*` и импорт.
- **Ключ пары** `pairKey = hmac(platform.secret(), 'lesson:' + pair.id + ':' + pair.startedAt)`; шаг `step = floor((now − startedMs) / 15000)`; код шага — первые 8 hex-знаков `hmac(key, 'code:' + step)` как число `% 10000`, четыре цифры с нулями слева; QR-ключ шага — первые 16 hex-знаков `hmac(key, 'qr:' + step)`.
- **Пропуск:** `'pass1.' + body + '.' + hmac(platform.secret(), 'pass:' + body)`, где `body = encodeURIComponent(JSON.stringify({ pid, dev, exp }))`, `exp` — конец окна в мс. С токеном входа не путается: другая приставка и другая подписываемая строка.

## Правила времени (с числами)

`LESSON = { checkinMinutes: 5, stepSeconds: 15, wrongCodes: 5, expiredSteps: 4, startEarlyMinutes: 10, autoCloseMinutes: PAIR_MINUTES (90) }`.

Пример: звонок 08:00, «Начать пару» в 07:58:00.

| Момент | Что |
| --- | --- |
| 07:49:59 | `start_early` («Начать можно с 07:50») |
| 07:58:00 | старт; окно до 08:03:00; конец пары 09:28:00 |
| 07:58:00–07:58:14 | шаг 0; в 07:58:14 до смены кода 1 с |
| 07:58:15 | шаг 1; принимаются коды шагов 1 и 0 |
| 07:59:15 (шаг 5) | коды шагов 5, 4 — приняты; 3, 2, 1 — «код сменился»; 0 и шаг 6 — неверный |
| 08:03:00 | окно закрыто: «не был» всем без отметки, время отметки 08:03:00 |
| 09:28:00 | пара закрыта сама, `finishedAt` 09:28:00 |
| 09:30:00 | у непочатой пары с этим звонком — `start_late` |

### Task 5 (Л): QR-кодировщик

**Files:** Create `site/js/qr.js`, `tests/qr.test.js`. (Файл сайта, но чистый алгоритм без DOM — поэтому «Логика».)

**Produces:**

```js
export function qrMatrix(text);       // -> { version, size, mask, rows: Array<Array<boolean>> } (true — тёмный модуль), уровень коррекции M
export function rsRemainder(data, ecCount);   // -> number[] — коды Рида — Соломона над GF(256), многочлен 0x11d
export function formatBits(ecc, mask);        // ecc 'L' | 'M' | 'Q' | 'H' -> 15-битное число с маской 101010000010010
export function versionBits(version);         // 7 и выше -> 18-битное число (БЧХ, многочлен 0x1f25); меньше 7 -> 0
```

Режим «байты» (UTF-8 через `TextEncoder`), уровень M, версии 1–10 (наименьшая, в которую входит текст; ёмкость M в байтах: 14, 26, 42, 62, 84, 106, 122, 152, 180, 213), блоки и число кодов коррекции — по таблице стандарта ISO/IEC 18004 для уровня M версий 1–10. Длиннее 213 байт — `throw new Error('qr_too_long')`. Маска — из восьми по наименьшему штрафу (правила N1–N4 стандарта); при равенстве — меньший номер. Без `Math.random`, без DOM; один и тот же текст — одна и та же матрица. Рисует матрицу экран (задача 10) на `<canvas>`, с тихой зоной 4 модуля.

Таблица уровня M (сверка плана пересчитала числа с нуля — `preflight-u4/qrref.mjs`):

| Версия (M) | ЕС на блок | Блоки × данных | Всего | Остаточные биты | Центры выравнивания |
| --- | --- | --- | --- | --- | --- |
| 1 | 10 | 1×16 | 26 | 0 | — |
| 2 | 16 | 1×28 | 44 | 7 | 6, 18 |
| 3 | 26 | 1×44 | 70 | 7 | 6, 22 |
| 4 | 18 | 2×32 | 100 | 7 | 6, 26 |
| 5 | 24 | 2×43 | 134 | 7 | 6, 30 |
| 6 | 16 | 4×27 | 172 | 7 | 6, 34 |
| 7 | 18 | 4×31 | 196 | 0 | 6, 22, 38 |
| 8 | 22 | 2×38 + 2×39 | 242 | 0 | 6, 24, 42 |
| 9 | 22 | 3×36 + 2×37 | 292 | 0 | 6, 26, 46 |
| 10 | 26 | 4×43 + 1×44 | 346 | 0 | 6, 28, 50 |

- Выравнивающие узоры — во всех сочетаниях центров, кроме трёх, накрывающих поисковые.
- Данные чередуются по столбцам блоков (короткие блоки первыми), затем так же коды коррекции.
- Режим «байты» 0100; длина 8 бит для v1–9, 16 бит для v10; затем до 4 нулей конца, добивка до байта, байты 0xEC/0x11 по очереди.
- Маски (r строка, c колонка), тёмный где выражение = 0: 0 `(r+c)%2`; 1 `r%2`; 2 `c%3`; 3 `(r+c)%3`; 4 `(⌊r/2⌋+⌊c/3⌋)%2`; 5 `(r·c)%2+(r·c)%3`; 6 `((r·c)%2+(r·c)%3)%2`; 7 `((r+c)%2+(r·c)%3)%2`.
- Штрафы: N1 = 3 + (серия − 5), N2 = 3, N3 = 40, N4 = 10.
- Биты формата (бит 0 младший): 0–5 в (i, 8); 6 в (7, 8); 7 в (8, 8); 8 в (8, 7); 9–14 в (8, 14 − i). Вторая копия: 0–7 в (8, size − 1 − i), 8–14 в (size − 15 + i, 8).
- Биты версии: бит i в (⌊i/3⌋, size − 11 + i % 3) и в зеркальной клетке.
- Суммы сходятся для каждой версии; раскладка блоков v8–10, места бит и формулы масок — по памяти и эталонной реализации Nayuki, по тексту ISO/IEC 18004 не сверены.

**Не сверено проверяющим по тексту ISO/IEC 18004:** раскладка блоков версий 8–10, места бит формата и версии, формулы масок. Окончательная проверка — камерой телефона владельца на приёмке блока 1. Если камера QR не читает, сверка идёт с эталонной реализацией Nayuki (QR Code generator, MIT) — по ней, а не наугад; её код в проект не копируется.

**Produces:**

```js
export function checkinCurrent(store, platform, user);         // 'checkin.current' {} -> { pair }
export function checkinPass(store, platform, data);            // 'checkin.pass' { pairId, qr, device } -> { pass, checkinLeftMs }   (без входа)
export function checkinMark(store, platform, data, user);      // 'checkin.mark' { pairId, device, code? | pass? } -> { result, … }
```

`checkin.current` → `{ pair: null | { id, subjectName, roomName, startTime, teacherName, phase ('checkin' | 'lesson'), checkinLeftMs, mark: null | { status, at: 'HH:MM' }, attemptsLeft } }` — идущая сегодня пара группы студента (после досчёта; если вдруг две — меньший № пары). `mark` — только своя отметка; `attemptsLeft` = 5 − его неверные коды на этой паре (не меньше 0). Ни кода, ни QR-ключа, ни чужих имён.

`checkin.pass` (публичное): `device` не `isDevice`, `qr` не строка, `pairId` не строка — `bad_request`; пары нет или она не `running` — `not_running`; окно закрыто (`phase !== 'checkin'`) — `window_closed`; `matchCode(..., 'qr', ...)`: `expired` — `code_expired`, `wrong` — `bad_code`. Иначе `{ pass: issuePass(platform, { pairId, device, exp: checkinEndMs }), checkinLeftMs }`. Ничего не пишет (кроме досчёта).

`checkin.mark` — порядок проверок (первая сработавшая отвечает; до шага 7 ничего не пишется):

1. `device` не `isDevice`; не ровно одно из `code` и `pass` задано строкой — `bad_request`. `pairId` не строка или пары нет — `not_found`.
2. Группа пары не группа студента (`user.row.groupId`) — `forbidden`. (Выключенный студент сюда не доходит: `unauthorized` при входе.)
3. Пара не `running` — `not_running`; окно закрыто — `window_closed`.
4. У студента уже есть отметка на этой паре (любая, в том числе от преподавателя) — ответ `{ result: 'already', status, at: 'HH:MM' }` без записи.
5. Удачная строка «Отметок с телефона» этой пары с тем же `device` и другим студентом — `device_used`.
6. С пропуском: `readPass` → `null`, другая пара или другое устройство — `bad_pass`. С кодом: неверных кодов студента на паре уже 5 — `too_many_codes`; `matchCode(..., 'code', ...)`: `expired` — `code_expired`; `wrong` — **запись** строки `{ pairId, studentId, device, way: 'code', result: 'wrong', at }` и ответ `{ result: 'wrong_code', attemptsLeft }` (`ok: true`; см. Global Constraints).
7. Удача: `writeMarks(store, { pair, subject, items: [{ studentId, status: 'present', noCoat: false, activity: null }], existing: new Map(), actorId: user.id, at, source: 'code' | 'qr' })` и строка `{ …, way, result: 'ok' }`. Ответ `{ result: 'ok', at: 'HH:MM', subjectName }`.

Каждая таблица читается не больше одного раза; на Node и SQLite обработчик синхронный, поэтому два одновременных запроса одного студента не дают двух строк.

**Повторный старт той же пары** (после сброса отметок или «Завершить» без отметок): неверные коды и `device_used` считаются только по строкам «Отметок с телефона» с `at >= pair.startedAt`; `checkinMark` с пропуском сверяет `exp` пропуска с `checkinUntil` текущего старта (`exp` не равен `parseLocalDateTime(pair.checkinUntil)` — `bad_pass`), так что пропуск прошлого старта не проходит.

**Запрет удаления** (`backend/handlers/dir.js`, список `BLOCKERS`): студента со строками «Отметок с телефона» удалить нельзя — дописать `['checkins', (r) => r.studentId === id]` рядом с проверкой «Посещаемости»; тест — `dir.remove` такого студента отвечает `in_use`.
