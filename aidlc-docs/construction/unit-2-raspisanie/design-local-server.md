# Доработка 4 юнита 2: база и сервер на компьютере владельца, без Google

Дизайн от 22.11.2026. Решения владельца — в таблице решений `aidlc-state.md` (22.11.2026): база на компьютере, Google не используется; туннель — Tailscale; ежедневная копия — на диск C:. Владелец сказал «давай настроим» — дизайн принят вместе с этими ответами; разбивка ниже — решения координатора.

## Зачем

Google Apps Script отвечает 2–3 с и ограничен 30 одновременными запросами на весь колледж — для отметки по QR (юнит 3) это главный риск. Владелец всё равно переедет на сервер колледжа; база на его компьютере (он почти не выключается) сразу будет настоящей базой, которую потом переносят как архив. Сайт остаётся на GitHub Pages.

## Как устроено

```
браузер (телефон студента, ноутбук преподавателя)
   │  https://janybek.github.io/college-journal/   (сайт, GitHub Pages)
   │  запросы API → https://<имя>.ts.net/api        (Tailscale Funnel)
   ▼
компьютер владельца: сервер журнала (Node.js, тот же handleRequest)
   └─ база: один файл SQLite вне репозитория
   └─ копия раз в сутки → диск C:, 30 последних дней
```

- **Сервер** — тот же код, что у стенда (`backend/`, `handleRequest`), в рабочем режиме: без вымышленных людей, без сброса, без раздачи сайта (сайт — на GitHub), свой порт (не 5173 и не 5273), свой файл базы. Стенды `dev`, `dev:reset`, `dev:real` остаются как есть.
- **Хранилище SQLite** — новое хранилище с тем же интерфейсом, что память, файл и Google (`list`, `get`, `insertMany`, `updateMany`, `removeMany`), по таблице на каждый лист `core/schema.js`, колонки по схеме — чтобы файл читался и переносился. Встроенный модуль Node (`node:sqlite`, Node 24), без новых зависимостей. Запись нескольких листов одного запроса — одной транзакцией (закрывает «половину записи», из-за которой в доработке 3 остались N1 и M6).
- **Файл базы** — вне репозитория (например, `D:\Журнал колледжа — данные\journal.sqlite`): в открытый репозиторий настоящие данные не попадают никогда. Путь — в настройке сервера, не в коде.
- **Первый запуск** создаёт таблицы и администратора `admin` с временным паролем, который печатается только в окне сервера (как `setup` в Google). Владелец входит сам и меняет пароль.
- **Сайт** узнаёт адрес сервера из настройки сайта (`site/js/config.js` или аналог): вместо адреса Apps Script — адрес Tailscale. Сервер отвечает только своему сайту (CORS только для `https://janybek.github.io`) и стенду.
- **Ограничение попыток входа** — сразу (было в юните 3): сервер виден из интернета.
- **Автозапуск** при входе в Windows (как сервер «Мои чаты»), перезапуск при падении, журнал работы в файл рядом с базой. Сон компьютера владелец выключает сам (системная настройка), по инструкции.
- **Копия** — раз в сутки и при каждом запуске: целая копия базы средствами SQLite (не копирование открытого файла) на диск C:, хранятся 30 последних; проверка, что копия открывается.
- **Tailscale Funnel** — владелец ставит программу и входит сам; координатор включает Funnel на порт сервера и записывает постоянный адрес в `aidlc-state.md` (раздел «Выкладка»).
- **Google** — код Apps Script и `build:gas` остаются в репозитории запасными; живая публикация Apps Script не удаляется, но сайт к ней больше не обращается.

## Чего не делаем

- Переноса данных из Google: там только пробные данные.
- Своего домена и Cloudflare.
- Нескольких серверов, синхронизации, облачных копий.

## Чего нельзя допустить

- Настоящие данные или путь с ними в репозитории; пароль администратора в чате или в файлах.
- Сервер, который отвечает любому сайту (CORS `*`) или отдаёт файлы с диска.
- Копия, которую нельзя открыть, и молчание об этом.
- Потеря данных при выключении света посреди записи (SQLite с журналом WAL, транзакции).

## Остаётся исполнителю (плану)

Имена файлов и команд (`npm run serve` и т. п.), порт, устройство таблиц SQLite, способ автозапуска, формат журнала работы, как сайт выбирает адрес сервера (стенд — свой адрес, рабочий сайт — Tailscale), тесты (хранилище SQLite проходит те же проверки, что память и файл; транзакция откатывается при ошибке; CORS; ограничение попыток; копия открывается).
