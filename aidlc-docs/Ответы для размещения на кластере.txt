Ответы по журналу колледжа (для размещения на кластере)

1. КОД И СБОРКА

- Репозиторий: https://github.com/janybek/college-journal
  Он открытый, доступ давать не нужно.
- Язык: JavaScript, Node.js 24 или новее. Фреймворков нет. Сервер не использует ни одной сторонней npm-библиотеки, только встроенные модули Node (в том числе встроенный node:sqlite).
- Устройство:
  - сайт — статические файлы из папки site/, сейчас лежат на GitHub Pages;
  - сервер отдаёт только API. Адрес API для сайта задаётся в site/config.js.
- Запуск:
  - первый раз: node backend/node/server.js --init
    (создаёт базу и ключ подписи, один раз выводит временный пароль admin);
  - дальше: node backend/node/server.js
    Порт 5373 по умолчанию, меняется переменной JOURNAL_PORT.
  - npm run serve:start годится только для Windows-компьютера, в контейнере она не нужна.
- Dockerfile: готового нет, сделаем сами. Перед этим в коде нужны две небольшие правки:
  - сервер сейчас слушает только 127.0.0.1, для контейнера нужен 0.0.0.0;
  - адрес API в site/config.js нужно поменять на новый.
- Важно для кластера:
  - база — один файл SQLite, поэтому сервер работает в одном экземпляре (1 реплика);
  - нужен постоянный том для папки данных;
  - запрос бывает до 20 МБ (студенты сдают файлы), лимит размера запроса на прокси нужно поднять до 20 МБ.

2. ДАННЫЕ

- Где хранятся: с 22.11.2026 в базе SQLite (файл journal.sqlite) на компьютере владельца. Сервер доступен из интернета через Tailscale Funnel. Прежний вариант на Google Таблицах и Apps Script остался запасным, сайт к нему больше не обращается. Firebase нет.
- Файлы: работы студентов (до 5 файлов по 10 МБ на одну сдачу) и файлы силлабусов лежат в папке files рядом с базой.
- Объём: пилот — 3 группы и около 40 преподавателей. Настоящие списки студентов ещё не загружены, сейчас в базе пробные данные. Оплат в журнале нет: это журнал посещаемости и оценок.
- Выгрузка:
  - сервер сам делает копию базы раз в сутки и при каждом запуске, хранит 30 дней;
  - перенос на новый сервер — это перенос папки данных целиком (база + secret.key + папка files);
  - готовой выгрузки всего в CSV или JSON нет. Её можно получить из SQLite любым стандартным инструментом или небольшим скриптом, если понадобится.

3. БЕЗОПАСНОСТЬ

- Пароли хранятся только хешами, открытым текстом нигде. Схема своя: SHA-256 с солью, 100 повторов (у временных паролей 20). Это не bcrypt и не argon2. Так сделано из-за ограничений прежнего варианта на Google. На Node можно перейти на встроенный scrypt без новых библиотек.
- Защита входа:
  - после 10 неверных паролей за 15 минут вход для этого логина закрывается на 15 минут;
  - сессия — токен, подписанный HMAC-SHA256: у сотрудников живёт 7 дней, у студентов 30;
  - API принимает запросы только с адреса своего сайта (список разрешённых адресов в настройках).
- Логины: роли «староста» в журнале нет. Учётные записи студентов и сотрудников заводят администратор или деканат: по одной или загрузкой из Excel. Журнал сам выдаёт временный пароль из 8 символов, показывает его один раз и просит сменить при первом входе. Сброс пароля: студенту — деканат или администратор, сотруднику — администратор.
- Ключи и токены в коде: их нет. Ключ подписи secret.key создаётся при первом запуске и лежит в папке данных, в репозиторий не попадает. Ключей Google API нет. У запасного варианта на Apps Script настройки хранятся внутри самого Google, а не в коде.
- Кто пользуется: администратор, деканат, проректор (только смотрит), преподаватели и студенты. Студенты заходят с телефона, отмечаются на паре по QR-коду, сдают задания, смотрят оценки и силлабус.

4. НАСТРОЙКИ

- Переменные окружения (настройки берутся из них, если задана JOURNAL_DATA_DIR):
  - JOURNAL_DATA_DIR — папка с базой, ключом и файлами (обязательна);
  - JOURNAL_BACKUP_DIR — папка для ежедневных копий (обязательна);
  - JOURNAL_PORT — порт, по умолчанию 5373;
  - JOURNAL_ORIGINS — адреса сайта через запятую, только https: с них API принимает запросы;
  - JOURNAL_ALERT_DIR — папка для файлов-тревог (необязательна).
- Проверка работы: GET /health отвечает 200 и {"ok":true,"data":"journal"}. Она показывает только, что процесс жив, базу не проверяет.
- Журнал работы пишется в файл server.log в папке данных.
- Внешние сервисы: почты и внешних сервисов нет. Сайт ничего не загружает с чужих адресов, шрифты и библиотеки лежат в нём самом. Часовой пояс зашит в коде: Бишкек, UTC+6.
