# Журнал колледжа

Электронный журнал для колледжа: Google Таблица как база, Google Apps Script как сервер, сайт на GitHub Pages. Пилот: 3 группы, 40 преподавателей. С владельцем говорим по-русски, простыми словами.

## С чего начинать сессию

Прочитай `aidlc-docs/aidlc-state.md`: там текущая фаза, юнит и следующий шаг.

- Требования: `aidlc-docs/inception/ТЗ.md`
- Дизайн версии 1: `aidlc-docs/inception/design-v1.md`
- План текущего юнита: `aidlc-docs/construction/<юнит>/plan.md`

## Порядок работы (AI-DLC)

1. Версия 1 разбита на 6 юнитов, они идут по порядку.
2. На каждый юнит: план → согласие владельца → агенты пишут код и тесты → проверяющий → показ на локальном стенде → приёмка владельца → выкладка.
3. Агенты лежат в `.claude/agents/`: `journal-logic` (core/), `journal-server` (backend/, dev/), `journal-screens` (site/), `journal-reviewer` (только отчёт). Основная сессия — координатор: раздаёт задачи и принимает работу. Два агента не правят одни и те же файлы одновременно.
4. После каждого шага обновляй `aidlc-docs/aidlc-state.md`.
5. Решение, которое меняет то, что увидит пользователь, или устройство базы, сначала согласуй с владельцем и запиши в таблицу решений в `aidlc-state.md`.

## Команды

- `npm test` — все тесты
- `npm run dev` — локальный стенд на `http://localhost:5173` (данные вымышленные, пароль стенда в `dev/seed.js`)
- `npm run dev:reset` — стенд с чистыми данными
- `npm run build:gas` — сборка сервера для Apps Script в `build/gas/`

## Жёсткие правила

- Настоящие данные студентов и сотрудников в репозиторий не попадают никогда: репозиторий открытый.
- Пароли и ключи не пишутся в чат и не кладутся в код. В Google и GitHub владелец входит сам в браузере.
- `git push` и выкладка в Google — только по прямой просьбе владельца.
- Адрес опубликованного Apps Script не должен меняться: обновляй существующую публикацию, а не создавай новую.
